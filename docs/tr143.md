# TR-143 diagnostics: the tests an ISP already runs

Every ISP's management system can ask a gateway to ping, trace a route,
download or upload a file, and look up a name, and read back how it went. That
is TR-143, in TR-181's `Device.IP.Diagnostics.` and `Device.DNS.Diagnostics.`.
AIGW OS (v0.29) answers these standard requests the same way over USP, over
TR-069 and from home. AIGW's own [Diagnose](diagnose.md) and
[proactive care](proactive-care.md) are there on top: Diagnose names the cause,
and proactive care runs a nightly speed test that is a TR-143 download. A
`DownloadDiagnostics` the ISP runs that completes in 2 s or more also teaches the
gateway the line's speed (v0.44.1, [proactive-care.md](proactive-care.md)).

| Test | Asks for | Answers |
|---|---|---|
| `Device.IP.Diagnostics.IPPing()` | `Host`, `NumberOfRepetitions` (3), `Timeout` (ms, 1000), `DataBlockSize` (64), `DSCP` | `SuccessCount`, `FailureCount`, `Average/Minimum/MaximumResponseTime` (ms) and `...Detailed` (µs), `IPAddressUsed` |
| `Device.IP.Diagnostics.TraceRoute()` | `Host`, `NumberOfTries` (3), `Timeout` (ms, 5000), `DataBlockSize` (38), `DSCP`, `MaxHopCount` (30) | `ResponseTime`, `RouteHops.{i}.` (`Host`, `HostAddress`, `ErrorCode`, `RTTimes`), `IPAddressUsed` |
| `Device.IP.Diagnostics.DownloadDiagnostics()` | `DownloadURL` (http://), `TimeBasedTestDuration` (s; 0: the whole file), `DSCP` | `ROMTime`, `BOMTime`, `EOMTime`, `TCPOpenRequestTime`, `TCPOpenResponseTime` (with µs), `TestBytesReceived`, `TotalBytesReceived/Sent`, the `...UnderFullLoading` values and `PeriodOfFullLoading`, `IPAddressUsed` |
| `Device.IP.Diagnostics.UploadDiagnostics()` | `UploadURL` (http://), `TestFileLength` (1 MiB), `TimeBasedTestDuration` (chunked when set), `DSCP` | the same times, `TestBytesSent`, the totals |
| `Device.DNS.Diagnostics.NSLookupDiagnostics()` | `HostName`, `DNSServer` (empty: the gateway's own DNS), `NumberOfRepetitions` (1), `Timeout` (ms, 5000) | `SuccessCount`, `Result.{i}.` (`Status`, `AnswerType`, `HostNameReturned`, `IPAddresses`, `DNSServerIP`, `ResponseTime`) |

Each answer has `Status`: `Complete`, or TR-181's `Error_...`, for example
`Error_CannotResolveHostName`, `Error_MaxHopCountExceeded`,
`Error_InitConnectionFailed`, `Error_TransferFailed`, `Error_NoResponse`,
`Error_Timeout` or `Error_HostNameNotResolved` (in a lookup's result).
`Device.IP.Diagnostics.IPv4PingSupported` and the other capability parameters
say what this gateway can do: IPv4, HTTP, one connection.

## Asking

- **USP:** the five asynchronous commands. A test's outputs come in the
  `OperationComplete`, with TR-181's names, including `RouteHops.1.HostAddress`
  and `Result.1.Status` for the tables.
- **TR-069:** as every ACS does it. In one `SetParameterValues`, set the
  object's inputs and `DiagnosticsState = Requested`. When the session ends,
  icwmp runs the test (agd keeps answering meanwhile). When it is done, icwmp
  sends an Inform with `8 DIAGNOSTICS COMPLETE`, and the ACS reads the results
  from the same object (`DiagnosticsState` is then `Complete` or an
  `Error_...`). Changing an input afterwards makes `DiagnosticsState` `None`
  again, as TR-181 says.
- **prplOS:** prplOS keeps its own `Device.IP.Diagnostics.`; aigw-amx publishes
  only AIGW's own subtree.
- **At home:**

  ```
  $ agctl test ping 10.0.0.1 5
  5 of 5 answered: 1.84 ms on average (1.62 to 2.31), from 192.168.1.2
  $ agctl test download http://speedtest.example.net/100MB.bin 8
  received 98043904 bytes in 8.00 s: 98.0 Mbit/s (connection opened in 4.1 ms, from 192.168.1.2)
  $ agctl test dns example.com
  1 answered
    Success                      93.184.215.14            9 ms from 127.0.0.1 (NonAuthoritative)
  ```

  (illustrative), and `agctl test trace <host>`, `agctl test upload <url>
  [bytes|Ns]`; `agctl -j test ...` gives the outputs as JSON.

## How

One test of each kind at a time (a second one is refused until it is done,
with a message that says so), each in a child process of agd, killed if it runs
far beyond what it was given. The tests:

- **IPPing:** ICMP echo requests, one after the other.
- **TraceRoute:** echo requests with a TTL growing from 1. A hop that doesn't
  answer has an empty address.
- **DownloadDiagnostics:** an HTTP/1.1 GET, timed as TR-143 says: the TCP open,
  the request (ROM), the first byte of the answer (BOM), the last (EOM). The
  totals come from the interface's counters.
- **UploadDiagnostics:** an HTTP PUT of `TestFileLength` bytes. A time-based
  test is sent chunked and ends after `TimeBasedTestDuration`; EOM is the
  server's answer.
- **NSLookupDiagnostics:** A queries, with the answers' addresses and whether
  they were authoritative.

Diagnostics only measure: like Diagnose, a management system may run them
without `mgmt.actions`. Not supported (the capability parameters say so): IPv6,
FTP and HTTPS URLs, more than one connection, per-connection and incremental
results, UDPEcho and ServerSelection.

## Tests

- `tests/test_tr143.c` (unit): URLs (http only), HTTP answer heads, TR-106 times
  with microseconds, status names, defaults.
- `tests/tr143-test.sh` (CI): agd with a local HTTP server and DNS responder.
  - IPPing: answered, and not answered (`FailureCount`); a name that doesn't
    resolve.
  - TraceRoute: its hops in the outputs and in the object.
  - Download: a whole file with TR-143's times in order, time-based on an
    endless stream, a 404, nothing listening, an https URL, one at a time.
  - Upload: by length, and time-based (chunked).
  - NSLookup: an answer, and a name not known.
  - The TR-069 way, through the data model: `Requested`, run, results,
    `None` after an input changes.
  - `agctl test`.
- `tests/usp-test.sh` (CI): a USP controller runs `IPPing()` and
  `TraceRoute()` and reads their outputs.
- `tests/cwmp-test.sh` (CI):
  - part 1: `IPPing()` through bbfdm, as icwmp calls it;
  - part 2: a real ACS over icwmp requests IPPing and a 2 MB download, gets
    `8 DIAGNOSTICS COMPLETE` and reads the results.
