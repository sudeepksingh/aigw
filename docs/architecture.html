AIGW OS Architecture

The AI-powered operating system for home gateways.

One small AI core turns any OpenWRT router, or any PC acting as a Wi-Fi access point, into a gateway that knows who is home, what every device and IoT gadget does, what is normal, and what to do about it. It works fully inside the home, gets smarter with optional cloud services outside, and everything around the core is a plug-in.

< 1 MBflash for the core
< 16 MBRAM, fits 128 MB routers
< 2 msAI decision per new connection

01Vision and design rules

Every component is either a sensor that feeds facts to the AI, or an actuator that carries out its decisions. The intelligence lives in one place, and everything else plugs into it.

R1

AI-centric

Components publish typed events and expose actions. None of them hard-codes policy.

R2

Plug and play

Sensors, models, actions and integrations are plug-ins that wire themselves in. Zero configuration on first boot.

R3

Inside first, outside optional

Everything essential runs on the gateway. Cloud services add fleet intelligence, never a dependency.

R4

Never break the home

Fail-open: if the AI stops, traffic and DNS keep working with the last safe policy.

R5

Small and portable

C core, fixed-size tables, same code and API on an OpenWRT router and on a PC acting as AP.

R6

Explainable and reversible

Every decision carries reasons, confidence, a time limit and an undo.

R7

Observe → advise → enforce

New capabilities start by watching, then suggest, and act only when trusted.

R8

Private by design

Raw data stays home. Only consented, anonymized features ever leave.

02Runs anywhere

Two first-class hosts and one combined mode. The same packages, the same API and the same plug-ins on every one of them.

host

OpenWRT router

Install on any OpenWRT 23.05+ device with 128 MB RAM or more. The router itself becomes the AI gateway.

opkg install aigw
Best for: homes, ISPs, router makers, small offices.
host

PC as AP

A Linux PC (or Windows with WSL2) plus a USB Wi-Fi adapter becomes the access point. Devices join its Wi-Fi; the PC forwards to the existing router.

agctl host setup --ap wlan1
Best for: developers, labs, demos, offices with a spare PC. Heavy models can run on the same machine.
combined

Router + companion

The OpenWRT router runs the core. A PC, NAS or cloud service runs the cortex for training, history and LLM features.

agctl cortex pair https://…
Best for: power users and managed services.

    The front-door camera asks for x7f3k9q2.top, a name it has never used.

    The domain model scores it 0.94 "machine-generated". The camera's baseline has 3 known domains; this isn't one.

  7. t + 3 snotify

  8. latercortex

    With consent, an anonymized indicator joins the fleet threat model, so other homes block it on first sight.

05System overview

Sensors push events into one brain; the brain writes labels that the kernel applies at packet speed. The cortex outside is optional.

Never

Thinks.

06Plug and play

Everything around the core is a plug-in. A plug-in declares what it produces and needs; the brain wires it in automatically and new AI capabilities switch on by themselves.

SensorFeeds events: a Zigbee dongle, a smart meter, a camera's motion feed.
ActuatorCarries out actions: a VLAN switch, a smart lock, a Matter command.
ModelA signed .agm file that turns features into scores.
SkillA bundle: policies + models + an app card, e.g. "Elder care" or "IoT lockdown".
ConnectorLinks outside: Home Assistant, an ISP portal, a care provider, a threat feed.

A plug-in manifest

{
  "name":    "ag-sensor-zigbee",
  "kind":    "sensor",
  "version": "0.3.0",
  "emits":   ["iot.zigbee.attr", "iot.zigbee.join"],
  "needs":   ["usb:serial"],
  "caps":    [],
  "budget":  { "ram_kb": 900, "cpu_pct": 2 },
  "hosts":   ["openwrt", "linux"]
}

What happens on install

  1. AnnounceThe plug-in registers ag.plugin.<name> on ubus with its manifest.
  2. CheckThe brain verifies signature, permissions and RAM/CPU budget.
  3. WireIts events flow into the Context Graph; its actions join the actuator list.
  4. ActivateAny model whose inputs are now available switches on, and the app shows the new capability.
opkg install ag-skill-iot-lockdown         # on an OpenWRT router
agctl plugin add ag-skill-iot-lockdown     # on either host

agdns · AI DNS

  • Forwarder, not a recursor: recursion and DNSSEC go to unbound or an encrypted upstream; AIGW adds policy and intelligence.
  • Keeps working alone: if agd is down, the last policy snapshot stays in force.
  • Predictive prefetch: a per-home "which name comes next" table resolves names before devices ask.
  • Bypass handling: port-53 redirect, the use-application-dns.net canary, DoH/DoT endpoint detection, dns.bypass events.
  • Hardening: fuzzed parser, ASan in CI, unprivileged with only CAP_NET_BIND_SERVICE, ujail + seccomp on OpenWRT.

agd · brain pipeline

  1. IngestOne uloop event loop. Built-in modules call directly; agdns and plug-ins use a Unix socket.
  2. IdentityMAC / IP / fingerprints → dev_id, person_id.
  3. Context GraphEntity tables joined by id, including the DNS ⇄ flow join.
  4. FeaturesStreaming, fixed memory: EWMA, count-min, HyperLogLog, bloom, windows.
  5. Inference.agm models, ≤ 2 ms per new flow.
  6. PolicyScores + user policies → an action from the ladder.
  7. GuardrailsLocal checks that even cloud or LLM proposals must pass.
  8. Decision logReasons, explain and revert over ubus.

Escalation ladder

Guardrails

  • Never touches the gateway itself, DHCP/DNS to the gateway, or devices you protect
  • Every enforcing action has a TTL and auto-reverts unless confirmed
  • Rate limit per device and per hour; block needs the highest confidence
  • Observe and advise modes never touch traffic

Kernel data plane

Fixed rules driven by data the brain writes. Its own table inet ag coexists with fw4 on OpenWRT and with plain NAT on a PC acting as AP.

table inet ag {
  set ag_quarantine { type ether_addr; timeout 1h; }
  set ag_dst_risky  { type ipv4_addr; flags timeout; }
  map ag_action { type mark : verdict; elements = {
      0x01 : accept, 0x02 : jump prio, 0x03 : jump bulk,
      0x04 : jump throttle, 0x05 : jump quarantine, 0x06 : drop } }

  chain forward {
    type filter hook forward priority filter - 5;           # before fw4 on OpenWRT
    ether saddr @ag_quarantine jump quarantine
    ip daddr @ag_dst_risky ct mark set ct mark | 0x0700     # DNS pre-label
    ct mark & 0xff == 0 ct packets < 6 queue num 0 bypass   # opt-in first-packet look, fail-open
    meta mark set ct mark
    ct mark & 0xff vmap @ag_action
  }
}

Cortex · outside

Bridge (C, on the gateway)

  • HTTPS (curl) with a per-gateway token, as an unprivileged plug-in
  • Exports state, alerts and decisions, never raw packets or DNS logs
  • Each report carries recent history: a missed one is covered by the next
  • Models go to agd, which accepts only signed ones (ed25519, usign-compatible); proposals wait for a person

Cortex services (Python)

  • Fleet history and training data (SQLite; a column store for large fleets later)
  • Training → .agm export → sign → OTA
  • Federated threat intelligence across homes
  • LLM agent as an MCP server; write tools only propose
  • Connectors: Home Assistant, ISP portals, care providers, feeds

Connection mark: the AI → kernel contract

bits 31–24flags / version
bits 23–16zone / trust
bits 15–8app class
bits 7–0action

Every decision also carries reason codes such as R_DGA_HIGH, R_NO_DNS_BEFORE_CONN, R_VOLUME_SPIKE, with the feature values behind them, so explanations are never invented after the fact.

10On-device AI runtime

A tiny interpreter instead of a general framework: no C++, about 25 KB, and models update without recompiling.

Tree ensemblesdevice type, flow app, domain risk~5 KB

.agm file: header (op family, input-schema hash, quantization), weights, ed25519 signature.

If the schema hash does not match the feature engine, the model is refused, so updates can't silently break.

11Policies

Written in UCI on both hosts, or produced from plain language by the LLM agent. Each policy compiles into DNS rules, nft set membership and a QoS class.

config policy 'kids_bedtime'
	option subject 'person:kids'
	option when    'daily 21:00-07:00'
	option match   'category:video category:social category:games'
	option action  'block'
	option mode    'enforce'

config policy 'iot_lockdown'
	option subject 'zone:iot'
	option match   'domain:!baseline'
	option action  'quarantine'
	option mode    'advise'

"Turn off the kids' games at 9 pm on school nights" → the agent drafts the policy above → the gateway validates it → you approve it in the app.

A sensor plug-in in C

#include <ag/plugin.h>

static void on_query(const struct ag_event *ev, void *ctx)
{
    const char *name = ag_ev_str(ev, "qname");
    if (ag_domain_in(name, "my-watchlist"))
        ag_emit(ctx, "custom.watch", AG_SEV_WARN,
                "dev_id", ag_ev_dev(ev), "qname", name);
}

AG_PLUGIN("watchlist", AG_KIND_SENSOR)
{
    ag_subscribe(plugin, "dns.query", on_query);
}

15Security and privacy

signed

Signed everything

Models, plug-ins and remote policies are ed25519-signed. Unsigned input is refused.

propose only

AI can't go rogue

Cloud and LLM only propose. Local guardrails and you decide.

local-first

As built in v0.6 (P3 act, complete)

PieceWhat it does
DecisionsAlerts flow through config policy sections into decisions on ag.decision (list · request · approve · reject · revert).
Modesadvise (default): proposals wait for a person · enforce: automatic, at most max_auto_per_hour · off: alerts only.
PriorityIP in nft set priority4/6; DSCP CS5 puts its traffic in the Wi-Fi (WMM) video queue.
DeprioritizeIP in nft set bulk4/6; DSCP CS1, the Wi-Fi background queue.
ThrottleIP in nft set throttle4/6 plus a per-device rate-limit rule, both directions; the rule checks the timed set, so it goes inert when the time is up.
Blockagdns answers NXDOMAIN for a name and its subdomains, over UDP and TCP, home-wide or for one device.
QuarantineMAC in inet ag quarantine (routed) and bridge ag quarantine (LAN-to-LAN through a bridge); forwarding only, so DHCP and DNS to the gateway keep working.
Disconnecthostapd deny list plus deauthenticate on every access point interface, lifted when the time is up.
GuardrailsNever the gateway, off-LAN or protected devices; TTL of 10 s to max_ttl on every action, enforced by the kernel and agdns themselves; blocking is never automatic; only well-formed MACs/IPs reach nft and hostapd; actions are re-applied after restarts, firewall reloads and hostapd restarts.

As built in v0.8 (P5 outside, first part)

StepWhat it does
AnswerRejecting a proposal, or undoing an automatic action, that came from a dga alert marks the name a false alarm; approving confirms it. The decision is the answer: nothing is asked twice.
ReportPlug-in ag-bridge (as nobody, HTTPS through curl, token in a file only it can read) sends status, models, alerts, decisions and devices to cortex: by name, anonymously or not at all. Never packets or DNS logs.
LearnCortex (Python, SQLite) turns those decisions into labels; retrain weighs each answer like 50 synthetic examples and records how far the model agrees with people.
PublishA version goes into the model's metadata; the file is signed with cortex's usign (Ed25519) key.
Checkagd accepts it only when a key you trust (agctl trust) signed it, it reads this build's features, gives sane scores, and is newer than the one in use and any you rolled back.
LoadSwapped in between two lookups: same process, no restart; agctl models shows version, signer and origin. A refused update leaves the running model, with the reason shown.
Undoagctl model rollback returns to the previous model and holds the newer one off, across restarts.
Ask (MCP)python3 -m aigw_cortex mcp: an AI assistant reads devices, alerts, decisions and models; its one write tool, propose_action, only suggests. The suggestion waits on the gateway for a person, even in enforce mode.

As built in v0.9 (P5 outside, complete)

PieceWhat it does
Remote accessWireGuard, one peer per phone: agctl remote add <name> shows a QR code for the WireGuard app, and the phone's private key is never stored. By default all its traffic goes home, so its lookups pass through AIGW anywhere; it appears as a device named after its peer. aigw-remote sets up the interface, DNS redirect, forwarding and NAT (and the firewall zone on OpenWRT).
Shared threat intelligenceCortex publishes a signed list of names people confirmed, or that several homes flagged, never ones anyone called a false alarm. Gateways load it like a model (same keys, versions, rollback); a lookup under a listed name raises known-threat, and the built-in policy quarantines.
Signed plug-insA trusted signature over every file of a plug-in folder grants its privileges without agctl plugin allow; any change takes that away.
Not yetIPv6 inside the tunnel; the OpenWRT firewall part on a real router (P6).

As built in v0.11 (P7 advanced, first part)

PieceWhat it does
DNS cacheagdns keeps answers for their TTL and serves them with the TTLs counted down: 0.3 ms instead of 51 ms against a 50 ms upstream in the test. Every answer still reaches the brain. agctl dns cache, LuCI overview.
PrefetchA name in use is asked for again just before it expires, so busy names never wait for the upstream (a 10 s name asked every half second for 14 s: slowest answer 1.4 ms).
Stale answersWhen the upstream fails, or is silent for 1.8 s, an expired answer is served with a 30 s TTL (RFC 8767): the home keeps working through an upstream outage.
Connection namesThe kernel copies the first packets of each new HTTPS connection to agd (NFLOG; a copy, nothing waits). agd reads the server name from the TLS ClientHello, or from the QUIC Initial, whose protection anyone can remove (RFC 9001). Connections an app made without AIGW's DNS (DNS over HTTPS, hard-coded addresses) get their real name, and that name is judged like a lookup: dga, known-threat, dns-bypass. A connection without any name still counts as "no DNS" after 3 s.
Not yetEncrypted Client Hello hides the site by design (the outer name is not judged); with fw4 flow offloading a name late in a two-segment post-quantum ClientHello can be missed.

As built in v0.12 (P7 advanced, second part)

PieceWhat it does
Both bands on a PCWith two USB adapters, aigw-ap runs a 5 GHz and a 2.4 GHz access point with one name, in one bridge, so a device keeps its address when it changes band. Channels up to 80 MHz wide (on the PC's adapter: 390 Mbit/s instead of 58.5). On WSL the adapters are attached from Windows automatically.
Band steeringClose devices move to 5 GHz (−60 dBm or better), far ones to 2.4 GHz (−75 dBm or worse): an 802.11v request where the device supports it, otherwise a 30-second refusal on its band. Hysteresis, a gap between moves, a home-wide rate limit, never protected devices; a device that won't move is left alone for a day. Works on dual-band OpenWRT routers the same way.
PresenceWho is home: ag.presence arrivals and departures (unseen for 10 minutes = left), and how near each Wi-Fi device is.
ProofA fake dual-band hostapd with six kinds of device, and in CI real hostapd and wpa_supplicant on simulated radios: the client joins on 2.4 GHz and AIGW's 802.11v request moves it to 5 GHz.
Not yetSteering across mesh nodes, room-level presence and motion from signal patterns.

As built in v0.13 (P7 advanced, third part)

PieceWhat it does
Channel self-healingAIGW measures how much of each access point's channel other networks use (the radio's survey). When it stays above 60 % for half an hour, one short scan scores the alternatives by the networks on and overlapping them, and a wifi-busy alert proposes the quietest. Approved (or automatic in enforce mode), hostapd announces the switch and devices follow without dropping; undo or the time limit switches back.
By handagctl channel 5 44: the same decision, with a time limit and undo.
ProofA fake hostapd with a crowded channel (proposal, switch, undo), and in CI a real hostapd moving the 5 GHz access point while the real client follows.
LimitsNeeds a radio that reports channel time and announces switches (router chipsets such as mt76 and ath10k/11k). The PC's RTL8821CU does neither: there the channel isn't judged, and a manual switch restarts the access point.

As built in v0.14 (P7 advanced, fourth part)

PieceWhat it does
Federated learningYour answers to alerts (a false alarm undone, a threat approved, or agctl label) stay on the gateway. In a round it trains a small shared layer (14 numbers) over the domain-risk model on them and sends cortex only the change, clipped and with noise added. Cortex averages the homes and publishes a signed layer; every gateway checks it before use.
GuardsA layer must keep flagging generated names (also behind www.) and the threats you named, and keep popular sites below the line; otherwise the gateway refuses it, without naming your names in the refusal.
PrivacyNo names, features or verdicts leave. agctl fed shows the privacy spent (ε, about 5 per round at the default noise); a budget stops taking part at a limit. With alert_names 0 the bridge's reports carry no alert names either.
ProofThree homes on one PC with a private cortex: a Polish home's false alarms score lower in every home (also a Polish name nobody answered about), threats still alert, and none of the names reaches cortex.
LimitsNoise strong enough for a meaningful ε needs many homes to learn anything; CloudFront-style hash names look like generated ones and are refused, so they belong on an allow list.

As built in v0.15 (P7 advanced, fifth part)

PieceWhat it does
Fast pathEstablished connections of devices AIGW isn't acting on go through the kernel's flowtable (or the switch chip on routers that have one) and skip the forwarding rules. When an action starts on a device, AIGW sends its connections back through the rules, so quarantine, throttle and priority still hold. Off by default until measured on a real router.
Traffic meterA tiny eBPF program on each LAN interface counts every device's traffic in the kernel: its rate right now, also for fast-path connections. Written out as instructions inside agd, so no BPF compiler is needed; it only counts, and disappears when agd stops.
ProofIn CI: an offloaded download still counted and metered, sent back by a throttle, cut off by quarantine, offloaded again after undo. The meter's rates match the transfers, and it runs inside OpenWRT on x86, MIPS and ARM.
LimitsThe PC's kernel has no flowtable (the fast path is for routers). What the switch chip forwards isn't seen by the meter. Speed gains on real routers are not measured yet.

As built in v0.16 (P7 advanced, sixth part)

PieceWhat it does
Model back-endsA router's NPU, DSP or a faster library can compute AIGW's model through one small C interface. A package puts its library in a root-only folder; AIGW uses it only after it gives the reference's verdicts on 300 probe names, and picks the fastest that does.
Built inThe reference interpreter, and a faster layout of the same trees that gives bit-identical scores.
ProofAn example library computing in 32-bit floats passes and can be chosen; a broken one is refused and the reference stays; the verdicts are the same whoever computes them.
LimitsNo real NPU back-end yet: each vendor's SDK is needed. A guide for router makers is in docs/model-backends.md.

As built in v0.17: behaviour instead of names

PieceWhat it does
The gapThe name model flags 93–99.6% of hex and base32 names, but 12.7% of pronounceable generated names and none made of dictionary words (rivergarden.net).
Home memoryEvery site that works for anyone in the home, in two small Bloom filters (the last 4,000–8,000 sites), kept over restarts.
dga-burstA device whose lookups of names nobody here ever used keep getting "no such name" (8 in 10 minutes, 75% of its never-used names) is hunting for its control server. The name that finally answers is named, with the command to block it; a quarantine is proposed.
ProofAn infected laptop's 25 word-like names: the name model flags 3, the burst alert comes at the 8th failure and names the server. No alert for a phone visiting 40 new sites with typos, a TV retrying a dead name, a filtering resolver's 0.0.0.0, or names AIGW blocks.
LimitsA slow generator (under 8 tries in 10 minutes) and lookups that bypass AIGW (DNS over HTTPS, reported as dns-bypass) are not caught by this signal.

As built in v0.18: managed by an ISP over USP (TR-369)

PieceWhat it does
One data modelIn agd (ag.dm): TR-181 devices and Wi-Fi, plus AIGW OS's alerts and decisions, with commands and events. USP and TR-069 both use it; the protocol clients only translate.
USPThe Broadband Forum's own agent, OB-USP-Agent (as in prplWare and RDK-B), unmodified, with AIGW OS's plug-in aigw-usp. Over MQTT 5 with TLS.
The home decidesOff by default. An ISP may read, and approve, reject or undo AIGW's proposals; quarantine, block and the mode only with mgmt.actions 1; the names devices looked up only with mgmt.alert_details 1. Guardrails always hold.
ProofA real USP controller over MQTT: reads devices, receives an alert as a USP event, approves a quarantine that lands in the firewall and undoes it, is refused what the settings forbid and a protected device. The published data model file is checked against what the gateway serves.
LimitsWi-Fi settings are read-only; no firmware upgrade or WebSocket transport yet.

As built in v0.19: managed over TR-069 too

PieceWhat it does
The clientiopsys's icwmp, unmodified (chosen over easycwmp: maintained, BSD-3-Clause, only standard OpenWRT libraries). Its data model comes from AIGW's small daemon aigw-cwmp-dm, over ubus.
The same data modelThe same devices, numbers and rules a USP controller gets, from agd. A SetParameterValues is all or nothing, applied when icwmp commits.
What CWMP lacksCommands become Device.X_AIGW_.Request. (a command and its inputs in one SetParameterValues, the result read back). Events become Device.X_AIGW_.LastEvent., sent as an active notification. The ACS's own settings (ManagementServer) are saved in /etc/config/aigw.
Prooficwmp against a Python ACS: the boot Inform, connection requests, reads, faults, an alert as 4 VALUE CHANGE, and an ACS-approved quarantine that lands in the firewall.
LimitsFirmware download over TR-069 is not handled yet; TLS client certificates are not configurable from /etc/config/aigw yet.

As built in v0.20: your names, not ours

PieceWhat it does
Vendor prefixAIGW's own names are TR-106 vendor extensions. The ISP or OEM that ships the gateway sets its prefix, X_<OUI>_ or X_<DOMAIN>_ (mgmt.vendor_prefix); X_AIGW_ is only the default. agd applies it to every path, command and event; USP, TR-069 and the published data model file follow.
IdentityManufacturer, model, product class, OUI and serial number are settings too, so the gateway reports itself as the OEM's product.
ProofThe data model test checks a prefix and names in every path, command and event, and a bad prefix refused; the whole TR-069 test, with icwmp and the ACS, runs under X_EXAMPLE-COM_.
